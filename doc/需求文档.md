# AsyncTask 需求文档

## 1. 概述

### 1.1 背景
在事件驱动 / Qt 的开发中，异步逻辑通常以回调、信号槽、状态机的方式实现，导致：
- 控制流被打散，代码难读难维护（“回调地狱”）；
- 阻塞式 API（如 `waitForConnected`、`waitForReadyRead`）会阻塞整个线程，无法在等待期间执行其他任务；
- 缺乏统一的异步任务编排、优先级与线程亲和控制手段。

AsyncTask（命名空间 `Coro`）基于 `boost::fiber`（有栈协程）提供一套**用户态协程异步框架**：把可暂停/恢复的逻辑封装为协程，协程被暂停时**让出所在线程而不阻塞它**，调用方可继续执行其它协程，待条件满足后协程被唤醒。使异步代码能像同步代码一样顺序书写。

### 1.2 目标用户
- 使用 Qt（含 network）开发、需要大量异步 IO / 信号等待的 C++ 开发者；
- 需要在少量线程上并发调度大量协程任务、并对优先级与线程归属有控制诉求的场景。

### 1.3 术语
| 术语 | 含义 |
|---|---|
| 协程 / fiber | 有栈用户态协程，暂停时让出线程、不阻塞线程 |
| 任务 FiberTask | 对协程执行结果的封装，支持链式编排（结构化并发） |
| 调度器 Scheduler | 自定义的 boost.fiber 调度算法，按优先级与线程亲和分发协程 |
| 优先级 Priority | Low / Normal / High |
| 线程亲和 Affinity | Shared（任意线程）/ Sticky（首次执行线程绑定）/ FixedId（指定线程） |
| 等待器 Awaitable | 生产者/消费者数据载体，消费方 `await` 取值 |
| 生成器 Generator | 把 Awaitable 当作数据流迭代 |

## 2. 功能需求

### FR-1 协程创建与执行
- FR-1.1 提供 `makeTask(fn, priority, affinity)` 将一个可调用体作为协程执行，返回 `FiberTask<T>`（T 为 fn 返回类型）。
- FR-1.2 提供 `launch_properties(fn, priority, affinity, name)` 直接创建带属性的 `boost::fibers::fiber`（低层接口）。
- FR-1.3 提供协程内让出/休眠：`Coro::sleep(s)`、`Coro::msleep(ms)`、`boost::this_fiber::yield()`。

### FR-2 调度：优先级与线程亲和
- FR-2.1 支持三级优先级 Low/Normal/High；同线程内高优先级先被调度。
- FR-2.2 支持三种线程亲和：
  - Shared：就绪时分配到任一可用线程执行；
  - Sticky：首次执行时绑定到某线程，此后固定在该线程；
  - FixedId：绑定到指定线程 id 执行。
- FR-2.3 提供全局工作线程池 `FibersPool`（默认 `max(硬件并发, 2)` 个工作线程），承接 Shared/Sticky/Fixed 协程。
- FR-2.4 跨线程调度：在无法运行协程的线程（如主线程阻塞）上创建的 Shared 协程，应能被其它工作线程取用执行。

### FR-3 结构化并发（FiberTask）
- FR-3.1 `then(fn)` / `then(fn, priority, affinity)`：链式定义后继任务，后继默认继承前驱的优先级与线程模型；前驱结果作为 fn 入参。
- FR-3.2 `on_finally(fn)`：注册任务链全部结束后执行的回调（可注册多个）。
- FR-3.3 `cancel()`：取消任务链，取消后未开始的后继任务不再执行其函数体，返回中断错误。
- FR-3.4 `get()`：阻塞（协程内让出）等待任务结果，返回 `Result<T>`。

### FR-4 结果与错误传递
- FR-4.1 提供 `Result<T, E=std::error_code>`（仿 C++23 `std::expected`），支持 `void` 与携带错误码，提供 `has_value()`/`value()`/`error()`/`value_or()`。
- FR-4.2 协程内抛出异常或被取消时，`Result` 以错误码（如 `errc::interrupted`）返回，不跨协程传播异常。

### FR-5 统一的协程等待接口（await 层）
- FR-5.1 提供 `Awaitable<T>` 作为唯一的等待/数据载体：生产者 push、消费者 `await`；跨线程安全；move-only 按值传递；析构即取消订阅（RAII，通过 `setOnClose`）；与 Qt 解耦。
- FR-5.2 提供统一工厂 `coro(...)`（参考 qcoro，单一重载入口）返回 `Awaitable<T>` 或对象包装器：
  - `coro(obj, &T::signal)` / `coro<Types...>(obj, &T::signal)`：等待 Qt 信号；
  - `coro(QIODevice*)` / `coro(QAbstractSocket*)` / `coro(QTcpServer*)` / `coro(QLocalSocket*)`：返回镜像原 Qt API 方法名的包装器（`readAll` / `waitForConnected` / `connectToHost` / `nextConnection` …），方法返回 `Awaitable`；
  - `coro(std::future<T>&&)` / `coro(QFuture<T>)`：等待 future。
- FR-5.3 提供对称的消费自由函数：`await(a)`、`await_for(a, timeout)`、`generate(a)`。
- FR-5.4 `Generator<T>` 支持 `for(auto v : generate(a))` 流式消费与 input-iterator 迭代、`next()`、`close()`。

### FR-6 Qt 集成
- FR-6.1 提供支持 Qt 事件循环的调度器 `QtFiberScheduler`（在 `suspend_until` 中驱动 `QEventLoop::processEvents`），使协程调度与 Qt 事件循环共存于同一线程。
- FR-6.2 提供主线程/QThread 专用调度器 `QtLocalFiberScheduler`（只接受 Fixed/Shared 协程）与支持协程的 `QtFiberThread`。
- FR-6.3 提供 `FiberApplication`：`installFiberApplication()` 安装、`Coro::exec()` 运行、`Coro::quit()` 退出；退出时排空在途协程并处理其投递的 `deleteLater`，保证干净退出。

### FR-7 生命周期与安全退出
- FR-7.1 `Coro::quit()` 应主动触发关机流程：唤醒挂起在 `await()` 的协程、排空在途协程与事件、再停线程池并退出（避免协程活过 `QCoreApplication` 而崩溃/卡死）。
- FR-7.2 等待器在来源对象析构、或应用关机时应自动关闭，使等待/生成器收敛。

## 3. 非功能需求

- NFR-1 **非阻塞**：协程暂停只让出线程，不阻塞 OS 线程；等待 IO/信号期间线程可执行其它协程。
- NFR-2 **跨线程安全**：`Awaitable`/`FiberChannel` 支持跨线程的生产者/消费者；全局队列访问受锁保护。
- NFR-3 **可裁剪**：await 层各来源包装器按头文件拆分，可按需 include；未使用 Qt/network 的项目不必拉入相关代码。框架依据项目配置（是否含 Qt core / network）自动启用相应功能。
- NFR-4 **可移植**：以 Linux + gcc 为主要目标；接口以标准 C++17 与 boost/Qt 为基础。
- NFR-5 **性能**：调度器在少量线程上支撑大量协程；等待器基于队列，构造/切换开销可控。

## 4. 约束与依赖

| 项 | 要求 |
|---|---|
| 编译器 | gcc ≥ 9.0，支持 C++17 |
| boost | ≥ 1.89.0（组件：fiber、context、thread、chrono） |
| Qt | ≥ 5.12（可选；启用 Qt core 时启用 Qt 调度器与信号/future 等待，启用 network 时启用 socket/server 等待） |
| 平台 | 主要支持 Linux（x86_64） |

## 5. 已知限制（现状）

- LIM-1 **运行时更改线程亲和不受支持**：线程归属应在协程创建时确定。运行中反复 `setAffinity` 迁移线程在高并发下会命中 boost.fiber 跨线程迁移的时序缺陷（睡醒的协程可能仍在原线程恢复执行），不保证正确迁移。
- LIM-2 **调度期 `deleteLater` 不即时派发**：Qt 在调度器嵌套 `processEvents` 时不派发 `DeferredDelete`，`deleteLater` 通常要到 `Coro::quit()` 排空时才处理。若需在协程执行期间等待某对象析构，应显式 `delete` 或另行处理。
- LIM-3 boost 1.89 源码包体积大，未随仓库提供，需按 `ReadMe` 自行下载编译安装。
