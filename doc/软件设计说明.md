## 3. 设计决策

从用户角度、不涉及内部实现细节，说明各构件将如何运行以满足需求及其设计原则；对系统状态/方式有依赖的，指明依赖性。

- **DD-1 有栈协程模型（满足 R1/R5）**：采用 `boost::fiber` 有栈协程而非 C++20 无栈协程。用户无需 `co_await`，以阻塞式 `await()`/`get()` 顺序书写异步逻辑；协程暂停只让出线程、不阻塞线程。原则：与既有 Qt 同步 API 心智一致、迁移成本低。
- **DD-2 带优先级与线程亲和的自定义调度（满足 R2/R6）**：用户通过 `Priority` 与 `Affinity` 指定协程在何线程、以何优先级运行；Shared 协程可跨线程分发，Fixed/Sticky 协程绑定目标线程（便于 Qt 对象线程亲和）。**依赖性**：线程亲和须在协程创建时确定，运行期不迁移（见 R1_OTHER）。
- **DD-3 统一等待载体 + coro() 工厂（满足 R5）**：所有异步来源经单一重载入口 `coro(...)` 归一为 `Awaitable<T>` 或镜像原 Qt API 的包装器；消费统一为 `await(a)`/`await(a,timeout)`/`generate(a)`。原则：把“等待什么”（来源）与“怎么消费”（取一次/超时/流式）解耦，接口一致、可发现（参考 qcoro）。
- **DD-4 等待载体与 Qt 解耦（满足 R5/R5_DESIGN）**：`Awaitable` 不含任何 Qt 类型，仅持共享 channel 与不透明生命周期守卫（`setOnClose`）；Qt 依赖集中在 `coro*` 工厂头，并按来源类型拆分文件。原则：可裁剪、可扩展非 Qt 来源。
- **DD-5 结果承载错误、异常不跨协程（满足 R4/R3）**：协程结果统一用 `Result<T,E>`；协程内异常在边界转为错误码。原则：结构化并发的确定性，避免异常跨协程栈传播。
- **DD-6 主循环模型与安全退出（满足 R6）**：以 `Coro::exec()`（`block.wait`）为主循环，Qt 事件由调度器 `processEvents` 泵；`Coro::quit()` 触发关机广播、排空在途协程与事件后再退出。**依赖性**：不得以 `QCoreApplication::exec()` 驱动（同线程互斥）；Qt 相关能力依赖宿主工程 `QT` 配置（core/network）启用。

## 4. 软件构建包括部件

### 4.1 软件单元
| 单元 | 目录 | 主要内容 |
|---|---|---|
| SU-1 基础层 | `coro/detail` | `Result<T,E>`、`FiberChannel<T>`、`launch_properties`/`sleep`/`msleep` |
| SU-2 调度层 | `coro/executor/scheduler` | `MetaContext`/`Affinity`/`Priority`、`FiberScheduler`/`QtFiberScheduler`/`QtLocalFiberScheduler`、`FiberGlobalQueue`/`FiberTaskQueue` |
| SU-3 执行器层 | `coro/executor` | `FibersPool`、`QtFiberThread`、`FiberThreadBlock` |
| SU-4 任务层 | `coro/task` | `FiberTask<T>`/`SharedState`、`FiberApplication` |
| SU-5 等待层 | `coro/await` | `Awaitable<T>`、`Generator<T>`、`coro()` 工厂与 `Coro*` 包装器、`detail/{signalpack,lifecycle}` |

### 4.2 软件结构
四层自底向上、上层依赖下层，Qt 能力按配置可选：

```
SU-5 await  ──uses──> SU-1(FiberChannel/Result), SU-4(FiberApplication 退出)
SU-4 task   ──uses──> SU-1(launch_properties/Result), SU-3(FibersPool)
SU-3 exec   ──uses──> SU-2(安装调度器)
SU-2 sched  ──uses──> SU-1, boost::fiber
```
详见 `doc/类图与时序图.md` 的分层与类图。

## 5. 执行方案

说明软件单元间的动态关系与控制/数据流；完整图示见 `doc/类图与时序图.md`，此处给出关键执行方案。

### 5.1 控制流与数据流：一次信号等待
- 控制流：用户协程 → `coro()`(SU-5) 建 `Awaitable` 并 connect 来源 → `await()` 让出协程（SU-1 channel 挂起）→ 信号槽 push 值 → 调度器(SU-2)唤醒协程 → 返回 `Result`。
- 数据流：来源数据 → 槽 push → `FiberChannel` → `await` pop → 用户。
- 对象生命周期：`Awaitable` 按值返回、由消费者持有；析构时经 `setOnClose` 断连（RAII）。

### 5.2 协程跨线程调度（动态创建/迁移）
主线程创建 Shared 协程 → 调度器 `awakened` detach 后入 `FiberGlobalQueue` Shared 桶 → 工作线程 `pick_next` 取出并 attach 运行；协程 `sleep/await` 时让出，线程可继续取其它协程。时序见 REF-3 §2.2。

### 5.3 任务链执行与状态
`makeTask`→`then`→`on_finally` 构成任务链，`SharedState.pending_cnt` 记在途节点，各节点完成 `done_nodes`，计数归零触发 `finally_cbs`；`cancel()` 置 `is_runnable=false`，后继节点运行前检查并短路。时序见 REF-3 §2.3。

### 5.4 进程/任务的动态创建与删除
- 工作线程：`FibersPool` 在首次使用时创建 N 个工作线程并安装调度器、`block.wait` 挂起；`FibersPool::close()` 唤醒使其退出。
- 协程：`launch_properties`/`makeTask` 动态创建 fiber，`detach` 后由调度器管理；协程返回即终止。
- 退出：`Coro::quit()` 触发 `aboutToQuit`→关闭各 `Awaitable` channel→排空在途协程与事件→关线程池→`exit()`。时序见 REF-3 §2.4。

## 6. 接口设计

### 6.1 接口标签和接口图
```
[用户代码]
   │ makeTask/then/get/cancel        (IF-1 任务与应用接口, SU-4/SU-1)
   │ coro/await/generate             (IF-2 等待接口, SU-5)
   │ Result/Awaitable/Generator/sleep(IF-3 基础接口, SU-1/SU-5)
   ▼
[AsyncTask]  ── IF-4 调度算法内部接口(SU-2↔boost.fiber) ── [boost::fiber]
             ── IF-5 全局队列内部接口(SU-2↔SU-2)
```

### 6.2 IF-1 任务与应用接口设计
- 优先级：高（核心对外 API）。
- 接口类型：C++ 函数/成员函数调用（头文件 `task/fibertask.h`、`task/fiberapplication.h`）。
- 数据元素：`fn`(可调用体)、`Priority`、`Affinity`、`Result<T>`。
- 通信方式：同步函数调用；`get()` 为协程内让出式阻塞。
- 接口协议：`makeTask(fn,pri,affine)→FiberTask`；`then/on_finally/cancel/get`；应用 `installFiberApplication/exec/quit`。

### 6.3 IF-2 等待接口设计
- 优先级：高。
- 接口类型：C++ 函数调用（头文件 `await/coro.hpp` 伞头或按需子头）。
- 数据元素：Qt 信号指针/Qt IO 对象/future；输出 `Awaitable<T>`/包装器/`Generator<T>`/`Result<T>`。
- 通信方式：工厂建立来源到 `FiberChannel` 的连接；`await` 为让出式阻塞，`generate` 为迭代。
- 接口协议：`coro(...)` 归一 → `await(a[,timeout])`/`generate(a)`；无参信号→`void`，多参→`tuple`；超时→`timed_out`，关闭→`no_message`。

### 6.4 IF-3 基础接口设计
- 优先级：中。
- 接口类型：C++ 类型/函数（`detail/result.hpp`、`await/awaitable.hpp`、`await/generator.hpp`、`detail/asyncdefine.h`）。
- 数据元素：`Result<T,E>`、`Awaitable<T>`、`Generator<T>`、时长。
- 通信方式：值语义/共享 channel。
- 接口协议：`Result::{has_value,value,error,value_or}`；`Awaitable::{channel,setOnClose,await,await_for,resolve,close}`；`sleep/msleep`。

### 6.5 IF-4 调度算法内部接口设计
- 优先级：高（框架正确性核心）。
- 接口类型：实现 boost.fiber `algorithm_with_properties<MetaContext>` 虚接口。
- 数据元素：`context*`、`MetaContext&`。
- 通信方式：boost.fiber 回调；`awakened/pick_next/suspend_until/notify/property_change`。
- 接口协议：须遵守 boost.fiber 对返回可运行上下文、`detach/attach`、pinned 上下文处理的约定。

### 6.6 IF-5 全局队列内部接口设计
- 优先级：高。
- 接口类型：`FiberGlobalQueue` 成员函数。
- 数据元素：`MetaContext`、`Affinity`。
- 通信方式：调用方须持有 `FiberScheduler::global_mtx`。
- 接口协议：`emplace_back/pop_front_affinity/getQueueSize/remove_*`。

## 7. 详细设计

### 7.1 SU-2 调度算法（IF-4/IF-5）
- 设计决策：以 `FiberGlobalQueue` 按 `Affinity` 分桶、桶内按 `Priority` 排序实现优先级+亲和；`awakened` 将非 pinned 协程 detach 后入全局队列，`pick_next` 按“本线程 Fixed→Sticky→未分配 Sticky→Shared”取出并 attach。`QtFiberScheduler` 在 `suspend_until` 用 `processEvents` 驱动 Qt 事件。
- 设计约束：跨线程队列访问由静态 `global_mtx` 串行化；须遵守 boost.fiber 上下文约定。
- 软件逻辑：见 REF-2 §3.2 及源码 `fiberscheduler.cpp`。**约束**：协程运行期不得更改线程亲和（R1_OTHER）。

### 7.2 SU-4 任务与应用（IF-1）
- 设计决策：`FiberTask` 持 `future<Result<T>>` 与共享 `SharedState`；`then` 链接后继并继承属性；`on_finally` 由计数归零触发；`cancel` 置标志短路。`FiberApplication::quit` 触发 `aboutToQuit` + 排空 + 停池。
- 设计约束：异常在协程边界转错误码；主循环用 `Coro::exec`。
- 软件逻辑：见源码 `fibertask.h`、`fiberapplication.cpp`。

### 7.3 SU-5 等待层（IF-2/IF-3）
- 设计决策：`Awaitable` 内部共享 `FiberChannel`（生产者只捕获 channel，避免引用环）、`setOnClose` 注入 RAII 断连；`coro()` 工厂按来源建立连接并注入 `bind_close`（来源析构/aboutToQuit→关闭 channel）；`readAll` 建连时若已有缓冲数据立即投递（规避 check-then-wait 竞态）；`generate(a)` 以 shared_ptr 持有 `Awaitable` 适配调度器对 fiber 函数的拷贝。
- 设计约束：`Awaitable` 不含 Qt 类型；Qt 依赖集中在 `coro*` 头。
- 软件逻辑：见源码 `await/awaitable.hpp`、`await/coro*.hpp`、`await/detail/*`。

### 7.4 SU-1 基础层（IF-3）
- 设计决策：`Result<T,E>` union 存值/错误、支持 `void`；`FiberChannel<T>` 以 `boost::fibers::mutex`+`condition_variable`+`deque` 实现跨线程安全队列（替代原生 unbuffered_channel）。
- 设计约束：并发访问受锁保护。
- 软件逻辑：见源码 `detail/result.hpp`、`detail/fiberchannel.hpp`。

### 7.5 SU-3 执行器（配合 IF-1/IF-4）
- 设计决策：`FibersPool` 单例管理工作线程并安装调度器；`FiberThreadBlock` 以 fiber 条件变量实现“阻止线程退出但允许协程调度”的挂起；`QtFiberThread` 为安装本地调度器的 QThread。
- 软件逻辑：见源码 `executor/fiberpool.cpp`、`executor/scheduler/fiberthreadblock.cpp`、`executor/qtfiberthread.cpp`。
