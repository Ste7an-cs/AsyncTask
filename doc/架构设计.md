# AsyncTask 架构设计

> 配套图示（类图 / 时序图）见 `doc/类图与时序图.md`。

## 1. 总体分层

AsyncTask（命名空间 `Coro`）自底向上分为四层，Qt 相关能力按编译配置可选启用：

```
┌───────────────────────────────────────────────────────────────┐
│ await 层  Awaitable / Generator / coro() 工厂 (信号/socket/future) │  统一等待接口
├───────────────────────────────────────────────────────────────┤
│ task 层   FiberTask / makeTask / FiberApplication                │  结构化并发 + 应用集成
├───────────────────────────────────────────────────────────────┤
│ executor 层  FibersPool / QtFiberThread / FiberThreadBlock       │  线程与执行器
│           scheduler: FiberScheduler / QtFiberScheduler /          │  自定义调度算法
│                      QtLocalFiberScheduler / FiberGlobalQueue     │  (优先级 + 线程亲和)
├───────────────────────────────────────────────────────────────┤
│ detail 层  Result / FiberChannel / asyncdefine(launch_properties)│  基础设施
└───────────────────────────────────────────────────────────────┘
                         基于 boost::fiber (有栈协程)
```

目录对应：`coro/detail`、`coro/executor`（含 `scheduler`）、`coro/task`、`coro/await`。

## 2. detail 层（基础设施）

### 2.1 Result<T, E=std::error_code>
仿 C++23 `std::expected` 的轻量实现（`detail/result.hpp`）：用 union 存放“值或错误”，支持 `void` 特化与携带 `error_code`。协程结果统一用 `Result` 承载，正常返回值、异常/取消返回错误码，**不跨协程传播异常**。提供 `has_value()`/`value()`/`error()`/`value_or()` 及 `result_inner_type`/`flatten_result_type` 等类型萃取。

### 2.2 FiberChannel<T>
跨线程/跨协程安全的队列（`detail/fiberchannel.hpp`）：`push`/`pop`/`pop_wait_for`/`close`，用 `boost::fibers::mutex` + `condition_variable`。替代原生 `unbuffered_channel`（后者在非协程线程 pop 会 crash）。是 `Awaitable` 的底层载体。

### 2.3 asyncdefine
`launch_properties(fn, priority, affinity, name)`：new 一个 `MetaContext` 作为 fiber 属性并创建 `boost::fibers::fiber`，是“带调度属性地启动协程”的统一入口。另含 `msleep`/`sleep`。

## 3. executor / scheduler 层（调度核心）

### 3.1 调度属性 MetaContext / Priority / Affinity
`MetaContext : boost::fibers::fiber_properties` 携带每个协程的 `Priority`（Low/Normal/High）、`Affinity`（Shared/Sticky/FixedId + 线程 id）与 name。`setPriority`/`setAffinity` 变更属性并 `notify` 调度器。

> 注意：`Affinity` 应在协程创建时确定；运行时反复迁移线程不受支持（见需求文档 LIM-1）。

### 3.2 FiberScheduler（自定义调度算法）
继承 `boost::fibers::algo::algorithm_with_properties<MetaContext>`，核心回调：
- `awakened(ctx, props)`：协程就绪时被调用。pinned（线程主/辅助上下文）留在本线程 `main_queue_`；其余 `ctx->detach()` 后按属性放入**全局队列** `FiberGlobalQueue`。
- `pick_next()`：按“本线程 Fixed → 本线程 Sticky → 未分配 Sticky（就地绑定到本线程）→ Shared”的顺序从全局队列取出协程，`attach` 到当前线程后返回；都没有则取本线程 `main_queue_`。
- `has_ready_fibers()` / `suspend_until()` / `notify()` / `property_change()`。

`FiberGlobalQueue`（`fibertaskqueue`）：全局单例，按 `Affinity` 分桶（`unordered_map<Affinity, set<MetaContext, greater>>`），桶内按优先级排序。跨线程访问由 `FiberScheduler::global_mtx`（静态）串行化。`FiberTaskQueue` 为其单桶版本，供测试与内部使用。

这样实现了**优先级 + 线程亲和 + 跨线程工作分发**：Shared 协程可被任意工作线程取走执行，Fixed/Sticky 协程只被目标线程取走。

### 3.3 QtFiberScheduler / QtLocalFiberScheduler
- `QtFiberScheduler`：在 `suspend_until` 中用 `QEventLoop::processEvents` 驱动 Qt 事件，使**协程调度与 Qt 事件循环共存于同一线程**——fiber 调度器作外层，Qt 事件在其空闲时被泵。
- `QtLocalFiberScheduler`：用于 Qt 主线程 / QThread，`pick_next` 只取 Fixed 与 Shared（不接受把新 Sticky 就地绑定），适合宿主线程。

> 关键约束：本框架**以 `Coro::exec()`（=`block.wait()`）作为主循环，不使用 `QCoreApplication::exec()`**。Qt 事件靠调度器的 `processEvents` 驱动；二者在同一线程互斥，不能用 `app.exec()` 驱动（否则主线程协程不被调度）。

### 3.4 FibersPool / QtFiberThread / FiberThreadBlock
- `FibersPool`：全局工作线程池，每个工作线程安装调度器并 `block.wait()` 挂起（线程不退出但协程可调度）；`close()` 解除挂起。
- `FiberThreadBlock`：用 fiber 条件变量让线程挂起等待、`close()` 唤醒——“阻止线程退出但允许其调度协程”的基元。
- `QtFiberThread`：`run()` 中安装 `QtLocalFiberScheduler` 并 `block.wait()` 的 QThread。

## 4. task 层（结构化并发）

### 4.1 FiberTask<T> 与 makeTask
`makeTask(fn, pri, affine)` 启动首个协程并返回 `FiberTask<T>`；`FiberTask` 持有 `future<Result<T>>` 与共享状态 `SharedState`。
- `then(fn[, pri, affine])`：创建后继协程，等待前驱 future 就绪后以其结果为入参执行，结果写入自身 future；后继默认继承前驱优先级与线程模型。
- `on_finally(fn)`：回调登记在 `SharedState.finally_cbs`，由计数（`pending_cnt`）归零时统一触发。
- `cancel()`：置 `SharedState.is_runnable=false`；后继协程运行前检查该标志，取消则以中断错误短路。
- `get()`：等待 future 并返回 `Result<T>`。

> `SharedState` 的 `add_nodes/done_nodes` 计数被测试覆盖、已确认正确，勿改。

### 4.2 FiberApplication（应用集成）
- `installFiberApplication()`：在主线程安装 `QtLocalFiberScheduler` 并启动 `FibersPool`。
- `Coro::exec()`：主线程 `block.wait()`，让主线程留在协程调度器中（协程与 Qt 事件都能跑）。
- `Coro::quit()`：**主动触发关机**——`QMetaObject::invokeMethod(qApp, "aboutToQuit")` 唤醒所有挂在 `await()` 的协程（各 awaitable 在 aboutToQuit 时关闭 channel），随后排空在途协程与事件（processEvents + yield + 处理 deleteLater），最后停线程池、退出。避免协程活过 `QCoreApplication` 而访问已销毁的事件系统崩溃/卡死。

## 5. await 层（统一等待接口）

### 5.1 Awaitable<T>
唯一的等待/数据载体（`await/awaitable.hpp`）：
- 内部 `shared_ptr<FiberChannel<T>>`（生产者只捕获 `channel()`，不持有整个 Awaitable，避免引用环）；
- `shared_ptr<detail::AwaitableCloseGuard> guard_` + `setOnClose(std::function<void()>)`：不透明 RAII 生命周期守卫；首次显式 `close` 或最终析构中先发生的一方恰好一次执行清理（如断开信号）。guard 在 mutex 保护下取出回调、在锁外执行用户清理；**本体与 Qt 完全解耦**；
- 通用 `Awaitable` 保持 move-only 的按值接口；`await()` / `await_for(timeout)` /
  `resolve()` / `close()` / `close(std::error_code)`。按值 `Awaitable`、`await`、
  `await_for` 与 `generate` 的既有重载仍受支持。
- `close()` 为正常终止，排空已入队数据后返回 `std::errc::no_message`；
  `close(error)` 记录第一个终止错误。`await_for` 返回 `timed_out` 时只结束当前
  等待，不关闭 channel、不取消订阅，也不取消或关闭来源。

### 5.2 消费接口
- `await(a)` / `await_for(a, timeout)`（`awaitable.hpp`，各自左值+右值重载）：取一次。
- `generate(a)`（`generator.hpp`）：把 Awaitable 适配为 `Generator<T>` 流式迭代（内部 shared_ptr 持有以适配调度器对 fiber 函数的拷贝）。

### 5.3 coro() 工厂（Qt 依赖集中层）
参考 qcoro，单一重载入口 `coro(...)`，按来源拆分为多个头（伞头 `coro.hpp` 一次性引入）：
| 头文件 | 提供 |
|---|---|
| `corosignal.hpp` | `coro(obj,&sig)` / `coro<Types...>(obj,&sig)` → `Awaitable<打包参数>` |
| `corofuture.hpp` | `coro(std::future/QFuture)` → `Awaitable<T>` |
| `coroiodevice.hpp` | `coro(QIODevice*)` → `CoroIODevice`（`readAll`/`waitForReadyRead`/`waitForBytesWritten`）|
| `corosocket.hpp` | `coro(QAbstractSocket*)` → `CoroAbstractSocket`（完整 TCP 方法见下）|
| `corotcpserver.hpp` | `coro(QTcpServer*)` → `CoroTcpServer`（`nextConnection`）|
| `corolocalsocket.hpp` | `coro(QLocalSocket*)` → `CoroLocalSocket`（完整本地 socket 方法见下）|
| `corolocalserver.hpp` | `coro(QLocalServer*)` → `CoroLocalServer`（`nextConnection`）|
| `coroudpsocket.hpp` | `coro(QUdpSocket*)` → `CoroUdpSocket`（`receiveDatagram`）|
| `corosslsocket.hpp` | `coro(QSslSocket*)` → `CoroSslSocket`（TLS 握手方法）|
| `detail/lifecycle.hpp` | 公共 `bind_close`：来源析构 / aboutToQuit → 关闭 channel |
| `detail/signalpack.hpp` | 信号参数打包模板 |

信号/future 等通用工厂按值返回 move-only `Awaitable`；socket 工厂的方法则返回
`std::shared_ptr<Awaitable<T>>`。后者由调用者和 Qt 回调强持有，避免等待期间过早
析构。两种形式均可被相应的 `await`、`await_for`、`generate` 重载消费。`readAll`
在建立连接时若已有缓冲数据立即投递，规避 check-then-wait 竞态。

### 5.4 Socket 包装器契约

所有以下方法运行于其 QObject 的所属线程；包装器会用 queued invocation 把发起
动作切换到该线程，调用者不得跨线程直接调用 QObject 方法，并须让对象活过等待。

| 包装器 | 返回 `std::shared_ptr<Awaitable<T>>` 的完整方法 |
|---|---|
| `CoroAbstractSocket`（`QTcpSocket`） | `readAll`、`waitForReadyRead`、`waitForBytesWritten`、`waitForConnected`、`waitForDisconnected`、`connectToHost(QString,quint16,OpenMode)`、`connectToHost(QHostAddress,quint16,OpenMode)`、`disconnectFromHost` |
| `CoroTcpServer` | `nextConnection`（`T=QTcpSocket*`） |
| `CoroLocalSocket` | `readAll`、`waitForReadyRead`、`waitForBytesWritten`、`waitForConnected`、`waitForDisconnected`、`connectToServer`、`disconnectFromServer` |
| `CoroLocalServer` | `nextConnection`（`T=QLocalSocket*`） |
| `CoroUdpSocket` | `receiveDatagram`（`T=QNetworkDatagram`） |
| `CoroSslSocket` | 继承 `CoroAbstractSocket` 全部方法，另有 `waitForEncrypted`、`connectToHostEncrypted` |

服务器 `nextConnection` 与 UDP `receiveDatagram` 是流式来源，交给 `generate` 后由来源
正常关闭结束迭代。UDP 每次产出一个完整 `QNetworkDatagram`，不改变 datagram 边界，
同时保留 payload、发送者/目标地址、端口等 metadata。普通远端关闭是
`no_message`；socket 错误为 `qt.socket`，local socket 错误为 `qt.local_socket`。
`sslErrors()` / `peerVerifyError()` 的证书和 peer verification 事件为 `qt.ssl`；
`QAbstractSocket` 的传输或握手失败可以为 `qt.socket`。`QSslSocket` 包装器不会自动调用
`ignoreSslErrors()`，证书策略必须由应用明确决定。

## 6. 关键数据流

### 6.1 一次信号等待
```
用户: await(coro(obj, &Obj::sig))
  coro(): 建 Awaitable a; connect(obj, sig, [ch]{ ch->push(打包参数); }); a.setOnClose(bind_close)
  await(a): a.await() -> ch->pop() 让出协程
  ...(信号触发)... 槽 push 值 -> pop 唤醒协程 -> 返回 Result<T>
  a.close() 或最终析构 -> guard 恰好一次执行 setOnClose 清理 -> disconnect
```

### 6.2 协程跨线程调度
```
主线程创建 Shared 协程 -> awakened(主线程调度器) -> detach + 入全局 Shared 桶
工作线程 pick_next() -> 取 Shared 桶协程 -> attach 到本线程 -> 运行
协程 sleep/await -> 让出 -> 该线程可继续取其它协程
```

### 6.3 干净退出
```
Coro::quit(): 触发 aboutToQuit -> 各 awaitable close channel -> 挂起协程被唤醒并收尾
              drainUntilIdle(): processEvents + yield 直到在途协程/事件跑完
              block.close() + FibersPool.close() + QCoreApplication::exit()
```

## 7. 设计取舍与注意事项

- **异常不跨协程**：协程内异常在边界被捕获并转为 `Result` 错误码，保持结构化并发的确定性。
- **等待与来源解耦**：`Awaitable` 不含任何 Qt 类型，Qt 依赖全部集中在 `coro*` 头；便于裁剪与将来支持非 Qt 来源。
- **主循环模型**：必须用 `Coro::exec()` 驱动（非 `QCoreApplication::exec()`）。
- **运行时改线程亲和**：不受支持，见需求文档 LIM-1；相关调度器竞态的排查记录见提交历史。
- **调度期 deleteLater**：不即时派发，见需求文档 LIM-2。
