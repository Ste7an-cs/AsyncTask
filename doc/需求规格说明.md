# AsyncTask 软件需求规格说明

## 1. 范围

### 1.1 标识
- 软件名称：AsyncTask（用户态协程异步框架）
- 命名空间：`Coro`
- 版本：见代码仓库提交记录
- 适用对象：基于 Qt / C++17 的异步、IO 密集型应用开发

### 1.2 概述
AsyncTask 基于 `boost::fiber`（有栈协程）提供一套用户态协程异步框架。它将可暂停/恢复的逻辑封装为协程：协程被暂停时**让出所在线程而不阻塞该线程**，调用方可继续执行其它协程，待条件满足后协程被唤醒。目标是使异步代码能像同步代码一样顺序书写，并提供带优先级与线程亲和的协程调度、结构化并发任务编排、以及统一的协程等待接口（信号 / socket / IODevice / future）。软件以头文件与静态库形式随宿主工程编译，依据宿主工程配置（是否含 Qt core / network）自动启用相应能力。

## 3. 需求

### 3.1 能力需求（RX_BASIC_ABILITY）

#### 3.1.1 协程创建与执行（R1_BASIC_ABILITY）

**3.1.1.1 功能需求**
应提供将可调用体作为用户态协程执行的能力，包括：以任务形式创建协程并获取其结果句柄；以低层接口创建带调度属性的协程；在协程内让出/休眠。

**3.1.1.2 输入输出**
- 输入：可调用体 `fn`、优先级 `Priority`、线程亲和 `Affinity`、可选名称。
- 输出：`FiberTask<T>`（T 为 `fn` 返回类型）或 `boost::fibers::fiber`。

**3.1.1.3 行为过程描述**
- `makeTask(fn, pri, affine)`：构造共享状态与 promise/future，经 `launch_properties` 启动协程执行 `fn`，将结果或错误写入 future，返回 `FiberTask<T>`。
- `launch_properties(fn, pri, affine, name)`：以 `MetaContext` 为 fiber 属性创建 fiber（低层）。
- `Coro::sleep(s)` / `Coro::msleep(ms)` / `boost::this_fiber::yield()`：协程内让出线程。

**3.1.1.4 行为参数**
- 优先级：Low / Normal / High（默认 Normal）。
- 亲和：Shared / Sticky / FixedId（`makeTask` 默认 fixed 到调用线程）。
- 异常条件：`fn` 抛出异常时在协程边界捕获，转为错误码结果（见 R4），不跨协程传播。

#### 3.1.2 优先级与线程亲和调度（R2_BASIC_ABILITY）

**3.1.2.1 功能需求**
应提供在少量工作线程上调度大量协程的能力，支持三级优先级与三种线程亲和，并支持跨线程工作分发。

**3.1.2.2 输入输出**
- 输入：协程的 `Priority` 与 `Affinity` 属性（`MetaContext`）。
- 输出：协程在满足亲和约束的线程上被取用执行。

**3.1.2.3 行为过程描述**
- 就绪协程经调度器 `awakened` 按亲和放入全局队列 `FiberGlobalQueue`（按 Affinity 分桶、桶内按优先级排序）。
- 各线程 `pick_next` 按“本线程 Fixed → 本线程 Sticky → 未分配 Sticky（就地绑定本线程）→ Shared”的顺序取出协程执行。
- 全局工作线程池 `FibersPool`（默认 `max(硬件并发, 2)` 个线程）承接协程。
- 在无法运行协程的线程（如主线程阻塞）上创建的 Shared 协程可被其它工作线程取用。

**3.1.2.4 行为参数**
- 亲和语义：Shared=任意可用线程；Sticky=首次执行线程绑定；FixedId=指定线程 id。
- 优先级：同线程内 High 优先于 Normal 优先于 Low。
- 异常条件：**运行时反复更改线程亲和（迁移线程）不受支持**（见 3.6 R1_OTHER），线程归属应在创建时确定。

#### 3.1.3 结构化并发（R3_BASIC_ABILITY）

**3.1.3.1 功能需求**
应提供任务链式编排能力：后继任务、结束回调、取消、结果获取。

**3.1.3.2 输入输出**
- 输入：前驱 `FiberTask<T>`、后继函数 `fn`、结束回调 `cb`。
- 输出：后继 `FiberTask<U>`；`get()` 返回 `Result<T>`。

**3.1.3.3 行为过程描述**
- `then(fn[, pri, affine])`：创建后继协程，待前驱 future 就绪后以其结果为入参执行 `fn`；后继默认继承前驱优先级与线程模型。
- `on_finally(cb)`：登记回调至共享状态，任务链全部结束（计数归零）时统一触发；可登记多个。
- `cancel()`：置共享状态不可运行；后继协程运行前检查该标志，已取消则短路并返回中断错误。
- `get()`：等待 future（协程内让出）并返回结果。

**3.1.3.4 行为参数**
- 前驱结果为错误或任务链已取消时，后继返回 `errc::interrupted`。
- 结束回调在任务链最后一个节点完成时触发，触发时机相对 `get()` 的先后由实现保证。

#### 3.1.4 结果与错误传递（R4_BASIC_ABILITY）

**3.1.4.1 功能需求**
应提供承载“值或错误”的结果类型，支持 `void` 与携带错误码，禁止异常跨协程传播。

**3.1.4.2 输入输出**
- 输入：正确值 `T` 或错误 `E`（默认 `std::error_code`）。
- 输出：`Result<T, E>`，可查询有无值、取值、取错误、带默认取值。

**3.1.4.3 行为过程描述**
`Result<T,E>` 以联合体存储值或错误，`operator bool()`/`has_value()` 判断状态，`value()`/`error()`/`value_or()` 取用；提供 `void` 特化与 `result_inner_type`/`flatten_result_type` 类型萃取。

**3.1.4.4 行为参数**
- 在 `has_value()==false` 时 `value()` 的返回不可用。
- 协程内异常在边界转为错误码（如 `errc::interrupted`）。

#### 3.1.5 统一协程等待（R5_BASIC_ABILITY）

**3.1.5.1 功能需求**
应提供统一的协程等待载体与工厂：单一重载入口 `coro(...)` 返回等待器 `Awaitable<T>` 或对象包装器；统一的消费函数 `await` / `generate`；等待器与具体来源（Qt/std）解耦。

**3.1.5.2 输入输出**
- 输入：Qt 信号（对象+成员信号指针）、Qt IO/socket/server 对象、`std::future`/`QFuture`。
- 输出：`Awaitable<T>` 或包装器（其方法返回 `Awaitable<T>`）；消费得到 `Result<T>` 或 `Generator<T>`。

**3.1.5.3 行为过程描述**
- 工厂：`coro(obj,&sig)` / `coro<Types...>(obj,&sig)`；`coro(std::future/QFuture)`；`coro(QIODevice*/QAbstractSocket*/QTcpServer*/QLocalSocket*)` 返回镜像原 Qt API 方法名的包装器（`readAll`/`waitForConnected`/`connectToHost`/`nextConnection`…）。
- 工厂内部：建 `Awaitable`，连接来源把数据 push 进其 channel，用 `setOnClose` 注入断连与关机收尾，按值返回。
- 消费：`await(a)` / `await(a, timeout)`（取一次）；`generate(a)`（流式迭代，`Generator<T>`）。
- `Awaitable<T>`：内部共享 `FiberChannel`，move-only 按值传递，析构即取消订阅（RAII），跨线程安全。

**3.1.5.4 行为参数**
- 信号无参→`Awaitable<void>`；单参→`Awaitable<Value>`；多参→`Awaitable<tuple<...>>`。
- `await_for(timeout)` 超时返回 `errc::timed_out`；channel 关闭返回 `errc::no_message`。
- `readAll` 在建立连接时若已有缓冲数据立即投递，规避 check-then-wait 竞态。
- 来源对象析构或应用 aboutToQuit 时，等待器自动关闭，使等待/生成器收敛。

#### 3.1.6 Qt 集成与安全退出（R6_BASIC_ABILITY）

**3.1.6.1 功能需求**
应提供与 Qt 事件循环共存的调度器、协程线程、应用集成与安全退出能力。

**3.1.6.2 输入输出**
- 输入：`installFiberApplication()`、`Coro::exec()`、`Coro::quit()`。
- 输出：主线程/工作线程可同时调度协程与处理 Qt 事件；退出时干净收尾。

**3.1.6.3 行为过程描述**
- `QtFiberScheduler`：在 `suspend_until` 中用 `QEventLoop::processEvents` 驱动 Qt 事件，使协程调度与 Qt 事件循环共存于同一线程。
- `QtLocalFiberScheduler`：主线程/QThread 专用（只取 Fixed/Shared）。`QtFiberThread`：支持协程的 QThread。
- `Coro::quit()`：触发 `aboutToQuit` 唤醒挂起协程 → 排空在途协程与事件 → 停线程池 → 退出，避免协程活过 `QCoreApplication` 而崩溃/卡死。

**3.1.6.4 行为参数**
- 主循环必须用 `Coro::exec()`（=`block.wait()`）驱动，**不得用 `QCoreApplication::exec()`**（二者同线程互斥）。
- 调度期 `deleteLater` 的 `DeferredDelete` 一般到 `quit()` 排空时才派发（见 3.6 R2_OTHER）。

### 3.2 外部接口需求（rx_interface）

#### 3.2.1 接口标识和接口图
外部接口以 C++ 头文件形式提供，宿主工程通过 `include(AsyncTask.pri)` 引入。主要公开接口分组：

```
task 层:   makeTask() / FiberTask<T>::{then,on_finally,cancel,get}
           installFiberApplication() / Coro::exec() / Coro::quit()
await 层:  coro(...) / await(a[,timeout]) / generate(a)
           Awaitable<T> / Generator<T>
基础:      Result<T,E> / Coro::sleep|msleep / launch_properties()
```

#### 3.2.2 任务与应用接口（R1_INTERFACE）
- `makeTask(fn, pri=Normal, affine=fixed(当前线程)) -> FiberTask<T>`
- `FiberTask<T>::then(fn[,pri,affine]) / on_finally(cb) / cancel() / get() -> Result<T>`
- `installFiberApplication()` / `int Coro::exec()` / `Coro::quit()`

#### 3.2.3 等待接口（R2_INTERFACE）
- `coro(obj,&sig)` / `coro<Types...>(obj,&sig)` -> `Awaitable<...>`
- `coro(QIODevice*/QAbstractSocket*/QTcpServer*/QLocalSocket*)` -> 对应包装器（方法返回 `Awaitable`）
- `coro(std::future<T>&&) / coro(const QFuture<T>&)` -> `Awaitable<T>`
- `await(a) / await(a, timeout) -> Result<T>`；`generate(a) -> Generator<T>`
- 头文件：伞头 `await/coro.hpp` 一次性引入；亦可按需单独引入 `corosignal/corofuture/coroiodevice/corosocket/corotcpserver/corolocalsocket.hpp`。

#### 3.2.4 基础接口（R3_INTERFACE）
- `Result<T,E>`：`has_value()/value()/error()/value_or()`
- `Awaitable<T>`：`channel()/setOnClose(fn)/await()/await_for(timeout)/resolve(v)/close()`
- `Generator<T>`：`begin()/end()/next()/close()`
- `Coro::sleep(s)/msleep(ms)`、`launch_properties(fn,pri,affine,name)`

### 3.3 内部接口需求（rx_in_interface）

- **R1_IN_INTERFACE 调度算法接口**：`FiberScheduler` 实现 boost.fiber `algorithm_with_properties<MetaContext>` 的 `awakened/pick_next/has_ready_fibers/suspend_until/notify/property_change`；子类 `QtFiberScheduler`/`QtLocalFiberScheduler` 覆写事件驱动与取任务策略。此为框架与 boost.fiber 的内部契约，实现须遵守 boost.fiber 对返回上下文与 detach/attach 的约定。
- **R2_IN_INTERFACE 全局队列接口**：`FiberGlobalQueue::{emplace_back, pop_front_affinity, getQueueSize, remove_*}`，供调度器在持有 `FiberScheduler::global_mtx` 时访问。
- **R3_IN_INTERFACE 线程阻塞接口**：`FiberThreadBlock::{wait,close}`，供线程池与 QtFiberThread 以“阻止线程退出但允许协程调度”的方式挂起/唤醒线程。
- 其余内部接口细节留待设计阶段（`doc/架构设计.md`）描述。

### 3.4 内部数据需求（rx_in_data）

- **R1_IN_DATA 队列数据**：`FiberChannel<T>` 为跨线程/跨协程安全队列（`boost::fibers::mutex`+`condition_variable`+`deque`），支持 `push/pop/pop_wait_for/close`；为 `Awaitable` 底层载体。
- **R2_IN_DATA 全局队列数据**：`FiberGlobalQueue` 以 `unordered_map<Affinity, set<MetaContext, greater>>` 按亲和分桶、桶内按优先级排序，另以 `unordered_map<context*, MetaContext>` 建立上下文索引；访问由静态 `global_mtx` 串行化。
- **R3_IN_DATA 任务共享状态**：`SharedState` 含 `pending_cnt`（在途节点计数）、`is_runnable`（取消标志）、`finally_cbs`（结束回调）；由任务链共享。
- **R4_IN_DATA 协程属性**：`MetaContext` 携带 `Priority`/`Affinity`/`name`；`Affinity` 含 `AffinityMode` 与可选线程 id。
- 数据一致性：全局队列与共享状态的并发访问须受相应锁/原子保护；`MetaContext` 的线程亲和应在协程创建时确定、运行期不迁移。

### 3.5 设计和实现约束（rx_design）

- **R1_DESIGN 语言/标准**：C++17（`gcc ≥ 9.0`）。
- **R2_DESIGN 依赖**：Boost ≥ 1.89.0（fiber/context/thread/chrono，静态链接，`/usr/local`）；Qt ≥ 5.12（可选）。
- **R3_DESIGN 构建**：qmake；`include(AsyncTask.pri)`；依据宿主工程 `QT` 配置（core/network）自动启用 Qt 调度器与信号/socket 等待能力。
- **R4_DESIGN 体系结构**：四层（detail / executor+scheduler / task / await），基于 boost.fiber 有栈协程；自定义调度算法实现优先级+线程亲和+跨线程分发。
- **R5_DESIGN 解耦与可扩展**：await 等待器 `Awaitable` 不含任何 Qt 类型，Qt 依赖集中于 `coro*` 工厂头；await 层按来源类型拆分头文件，支持按需引入与将来扩展非 Qt 来源。
- **R6_DESIGN 主循环模型**：必须以 `Coro::exec()`（`block.wait`）作为主循环、由调度器 `processEvents` 泵 Qt 事件；不得以 `QCoreApplication::exec()` 驱动。
- **R7_DESIGN 平台**：主要支持 Linux（x86_64）。

### 3.6 其他需求（rx_other）

- **R1_OTHER 已知限制—运行时改亲和**：运行中反复 `setAffinity` 迁移线程不受支持，高并发下会命中 boost.fiber 跨线程迁移的时序缺陷（睡醒的协程可能仍在原线程恢复执行），不保证正确迁移。线程归属应在协程创建时确定。
- **R2_OTHER 已知限制—调度期 deleteLater**：Qt 在调度器嵌套 `processEvents` 时不派发 `DeferredDelete`，`deleteLater` 通常到 `Coro::quit()` 排空时才处理；需在协程执行期等待对象析构时应显式 `delete` 或另行处理。
- **R3_OTHER 交付物**：boost 1.89 源码包因体积未随仓库提供，需按 REF-1 自行下载编译安装到 `/usr/local`。
- **R4_OTHER 测试**：随仓库提供 5 套 QtTest 用例（testfibertask/testexecutor/test_scheduler/testfiberawait/testProfile）；测试 `.pro` 使用 `-static-libasan`（不与动态 `-lasan` 混用）。testProfile 为长时间压力测试，会超时属预期。

## 4. 注释

### 4.1 术语与缩写
| 缩写/术语 | 含义 |
|---|---|
| 协程 / fiber | 有栈用户态协程，暂停时让出线程、不阻塞线程 |
| Awaitable | 协程等待/数据载体，消费方 `await` 取值 |
| Generator | 把 Awaitable 当数据流迭代 |
| Affinity | 线程亲和：Shared/Sticky/FixedId |
| Priority | 优先级：Low/Normal/High |
| SRS | 软件需求规格说明（本文档） |

### 4.2 需求标识说明
- `RX_BASIC_ABILITY`：能力需求（X 为序号，如 R1_BASIC_ABILITY）。
- `rx_interface` / `rx_in_interface` / `rx_in_data` / `rx_design` / `rx_other`：分别为外部接口、内部接口、内部数据、设计约束、其他需求；具体条目以 `R<n>_INTERFACE` 等标识。
