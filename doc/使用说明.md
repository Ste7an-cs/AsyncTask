# AsyncTask 使用说明

AsyncTask 是一个基于 `boost::fiber`（有栈协程）的用户态协程异步框架，面向 Qt / C++17。协程在等待时**让出所在线程而不阻塞线程**，因此可以用同步风格的顺序代码书写异步逻辑，同时让大量协程在少量线程上并发运行。

本文面向使用者：讲清依赖与安装、快速上手、术语、协程的日常用法，以及如何为新的异步来源扩展自定义 Awaitable。需求与设计的正式定义见 `doc/需求规格说明.md`（SRS）与 `doc/软件设计说明.md`（SDD）。

## 1. 第三方依赖

| 依赖 | 版本要求 | 组件 / 说明 |
|---|---|---|
| Boost | ≥ 1.89.0 | `fiber`、`context`、`thread`、`chrono`（另需 `atomic`、`date_time` 随编译产出）；静态链接，安装于 `/usr/local` |
| Qt | ≥ 5.12（可选） | `core` 启用 Qt 调度器与信号等待；`network` 启用 socket / server / UDP / SSL 等待 |
| 编译器 | gcc ≥ 9.0 | 需支持 C++17 |
| 构建工具 | qmake | 通过 `include(AsyncTask.pri)` 接入宿主工程 |

说明：
- boost 源码包**未随仓库提供**（体积原因），需自行下载编译安装（见 §2）。
- 不含 Qt 的工程也可使用核心能力（`Result` / `FiberChannel` / 调度器基类 / `FiberTask`）；Qt 相关能力按宿主工程 `QT` 配置自动启用。

## 2. 安装

### 2.1 编译安装 boost

```bash
# 下载并解压 boost 1.89
wget https://archives.boost.io/release/1.89.0/source/boost_1_89_0.tar.gz
tar xzf boost_1_89_0.tar.gz && cd boost_1_89_0

# 配置需要的组件
./bootstrap.sh --with-libraries=fiber,context,thread,chrono,atomic,date_time

# 编译并安装到 /usr/local（AsyncTask.pri 硬编码此路径）
sudo ./b2 -j$(nproc) cxxflags="-std=c++17" link=static variant=release \
     threading=multi debug-symbols=on install
```

也可进入 `3dParty/boost/` 使用 `sudo bash install.sh`（需先把源码包放入该目录）。

### 2.2 接入宿主工程

在工程 `.pro` 中加入（路径按实际调整）：

```pro
QT += core network            # network 仅在需要 socket 等待时加
CONFIG += console c++17
include($$PWD/path/to/AsyncTask.pri)
SOURCES += main.cpp
```

`AsyncTask.pri` 会校验 `/usr/local` 下的 boost 头与静态库，并按 `QT` 配置自动启用对应能力。

### 2.3 头文件

```cpp
#include "task/fiberapplication.h"   // installFiberApplication / exec / quit
#include "task/fibertask.h"          // makeTask / FiberTask / Priority / Affinity
#include "await/coro.hpp"            // 伞头：全部来源的 coro()/await()/generate()
#include "detail/asyncdefine.h"      // sleep / msleep / launch_properties
#include "executor/qtfiberthread.h"  // QtFiberThread（专用协程线程，可选）
using namespace Coro;
```

按需可只引子头：`await/corosignal.hpp`、`corofuture.hpp`、`coroiodevice.hpp`、`corosocket.hpp`、`corotcpserver.hpp`、`corolocalsocket.hpp`、`corolocalserver.hpp`、`coroudpsocket.hpp`、`corosslsocket.hpp`、`await/generator.hpp`。

## 3. 快速使用

最小可运行示例：

```cpp
#include <QCoreApplication>
#include <QTimer>
#include "task/fiberapplication.h"
#include "task/fibertask.h"
#include "await/coro.hpp"
using namespace Coro;

int main(int argc, char* argv[]) {
    QCoreApplication app(argc, argv);
    installFiberApplication();               // 安装调度器 + 启动工作线程池

    makeTask([]{
        QTimer timer; timer.start(500);
        await(coro(&timer, &QTimer::timeout));   // 同步风格等一个信号，不阻塞线程
        qDebug() << "timeout fired";
        quit();                              // 安全收尾并退出
        return 0;
    });

    return exec();                           // Coro::exec() —— 不是 app.exec()
}
```

三条铁律（违反其一是绝大多数问题的根源）：

1. **主循环用 `Coro::exec()`，不要用 `QCoreApplication::exec()`。** 协程调度器即主循环，Qt 事件由每线程的常驻泵协程分发；二者同线程互斥。
2. **退出用 `Coro::quit()`。** 它广播 `aboutToQuit` 唤醒挂起协程、排空在途任务、停泵、停线程池后退出；不调用会卡死或崩溃。
3. **所有 API 在命名空间 `Coro` 下。**

更多可运行示例见 `example/`（basic、signal_await、socket_pingpong、generator、thread_init）。

## 4. 术语定义

| 术语 | 定义 |
|---|---|
| 协程 / fiber | 有栈用户态协程。暂停时让出所在线程（线程转去执行其它就绪协程），不阻塞线程；由 boost.fiber 提供上下文切换 |
| FiberTask\<T\> | 一次协程任务的句柄：`then` 链式后继、`on_finally` 结束回调、`cancel` 取消、`get()` 让出式取结果 |
| Awaitable\<T\> | 协程等待/数据载体。生产者经 `channel()` 投递，消费者 `await`/`await_for` 取值；不含任何 Qt 类型 |
| FiberChannel\<T\> | 跨线程/跨协程安全的数据队列，Awaitable 的底层载体；`push`/`pop`/`close(error)` |
| Generator\<T\> | 把 Awaitable 当数据流迭代的适配器；`generate(a)` 后 range-for 逐个取用 |
| Result\<T,E\> | "值或错误"二选一的结果载体；一切失败以错误码表达，异常不跨协程边界 |
| coro(...) | 统一工厂：把 Qt 信号 / IO / socket / server / future 包装为 Awaitable 或镜像 Qt 方法名的包装器 |
| await / await_for / generate | 统一消费函数：取一次 / 带超时取一次 / 流式迭代 |
| Priority | 协程优先级：`Low` / `Normal` / `High`（默认 Normal） |
| Affinity | 线程亲和：`shared()` 任意工作线程 / `sticky()` 首次执行线程绑定 / `fixed(id)` 指定线程（makeTask 默认 fixed 到创建线程） |
| AutoDisconnect | socket 族包装器内部的连接生命周期管理器：一组 Qt 连接绑定断连条件（返回句柄失效 / 某信号[+判断]），条件成立即整组断开 |
| 泵协程 | 每个安装 Qt 调度器的线程上的常驻协程，空闲时代为分发 Qt 事件，使 Qt 回调运行在 worker 协程上（回调内可安全做协程阻塞） |

## 5. 怎么使用协程

### 5.1 创建任务与结构化并发

```cpp
auto task = makeTask([]{ /* 协程体 */ return 10; },
                     Priority::Normal, Affinity::sticky())
    .then([](int v){ return v + 1; })        // 前驱结果作为入参
    .on_finally([]{ qDebug() << "chain done"; });

Result<int> r = task.get();                  // 让出式等待结果，不阻塞线程
// task.cancel();                            // 取消：尚未开始的后继短路返回中断
```

多协程汇合（join）：捕获对方的 `FiberTask` 并 `get()`：

```cpp
auto job = makeTask([]{ /* 后台工作 */ return 1; });
makeTask([job]{ job.get(); quit(); return 0; });   // 等 job 完成后再退出
```

### 5.2 等待 Qt 信号 / future

```cpp
auto r  = await(coro(obj, &Obj::valueChanged));        // 单参信号 → Result<Value>
auto r2 = await(coro<int>(obj, &Obj::twoArgsSignal));  // 多参信号指定所需类型
auto r3 = await_for(coro(obj, &Obj::done), std::chrono::seconds(2));  // 带超时
auto v  = await(coro(std::move(fut)));                 // std::future / QFuture
```

信号参数与结果类型：无参 → `Result<void>`；单参 → 该值；多参 → 元组。

### 5.3 socket 收发与流式读取

```cpp
QTcpSocket* c = new QTcpSocket();
auto connected = await_for(coro(c).connectToHost(host, port), 2s);
if(connected){
    auto response = coro(c).readAll();       // 流式等待器：建一次，反复用
    c->write("ping");
    auto reply = await_for(response, 2s);    // 取一块数据
    // 或流式：for (const QByteArray& msg : generate(coro(c).readAll())) { ... }
}

// 服务端接受连接流
for (QTcpSocket* peer : generate(coro(server).nextConnection())) { /* ... */ }
```

要点：
- socket 族方法返回 `shared_ptr<Awaitable<T>>`；**流式等待器（如 `readAll`）建一次、对同一句柄反复 `await`/`generate`**。订阅随句柄析构自动取消，重复创建不会残留、不会互相截数据，但仍属反模式。
- `await_for` 超时只结束本次等待，**不取消订阅、不关闭 socket**；要停来源请显式调用 Qt 的断开/关闭 API。
- `close()` 是正常终止（余量先消费，随后 `no_message`）；socket 错误为保留 Qt 枚举值的 typed error（`qt.socket` / `qt.local_socket` / `qt.ssl`）。
- **QObject 线程亲和**：所有 Qt 对象操作都在其所属线程执行；把对象建在需要的线程，或用 `Affinity::fixed/sticky` 把协程绑到确定线程，不要把 Qt 对象放进 `Affinity::shared()` 任务。

### 5.4 让出、休眠与底层协程

```cpp
boost::this_fiber::yield();   // 让出时间片
sleep(1); msleep(100);        // 休眠（让出线程，不阻塞）

auto fb = launch_properties([]{ /* ... */ }, Priority::High, Affinity::shared());
fb.detach();                  // 低层接口：带调度属性直接建协程
```

### 5.5 专用协程线程

```cpp
QtFiberThread* worker = new QtFiberThread();
worker->start();              // 该线程可承载 fixed 协程，也参与 shared 协程调度
// ... 使用 ...
worker->quit(); delete worker;
```

### 5.6 常见错误

- 用 `app.exec()` 而非 `Coro::exec()`；忘记 `Coro::quit()`。
- 在协程内做真阻塞调用（`QThread::sleep`、Qt `waitForXxx`、`future.get()`）——阻塞整个线程；改用 `sleep`/`msleep`/`await(coro(...))`。
- 调度期 `deleteLater` 不即时派发（通常到 `quit()` 才处理）；需要即时释放用 `delete`。
- 运行期反复改线程亲和迁移协程不受支持；线程归属创建时确定。

## 6. 怎么扩展自定义的 Awaitable

`Awaitable<T>` 与来源完全解耦：扩展一个新异步来源 = 写一个 `coro(...)` 工厂重载，把"来源事件 → `channel->push`"接起来，并挂好收尾。有两种范式，按来源复杂度选择。

### 6.0 核心契约（两种范式都必须遵守）

1. **生产者只捕获 `channel()`（`shared_ptr<FiberChannel<T>>`），绝不捕获整个 `Awaitable`。** 回调若强持 Awaitable，会形成"来源→连接→awaitable"引用环，句柄永不析构、订阅永不释放（曾导致流式读 stall 的真实 bug）。
2. **终止即 `channel->close(error)`**：来源结束/出错时关闭 channel，令 `await` 返回错误、`generate` 自然收敛。正常结束用 `close()`（消费者最终观察到 `no_message`），异常用 `close(error_code)`（保留首个终止错误）。
3. **收尾恰好一次**：断开信号连接等清理动作要挂到 `Awaitable::setOnClose`（首次显式 `close` 或析构时执行一次）或交给 `AutoDisconnect`。
4. `push` 在锁内自判关闭状态，与 `close` 竞态安全；回调无需额外加锁。

### 6.1 范式一：轻量来源（一次性/简单流）——按值 Awaitable + bind_close

适合：一个主信号、来源析构或 `aboutToQuit` 即收尾的场景。参照 `coroiodevice.hpp` / `corosignal.hpp`：

```cpp
#include "awaitable.hpp"
#include "detail/lifecycle.hpp"

namespace Coro {

/// 示例：把 QProcess 的标准输出包成流式 Awaitable
inline Awaitable<QByteArray> coroStdout(QProcess* proc){
    Awaitable<QByteArray> a;
    auto ch = a.channel();                       // 只捕 channel（契约 1）
    QPointer<QProcess> guard(proc);

    auto c1 = std::make_shared<QMetaObject::Connection>();
    if(proc){
        *c1 = QObject::connect(proc, &QProcess::readyReadStandardOutput,
                               [ch, guard]{
            if(guard) ch->push(guard->readAllStandardOutput());
        });
        QObject::connect(proc,
                         qOverload<int, QProcess::ExitStatus>(&QProcess::finished),
                         [ch](int, QProcess::ExitStatus){ ch->close(); });  // 契约 2
        // 规避 check-then-wait 竞态：已有缓冲立即投递
        if(proc->bytesAvailable() > 0) ch->push(proc->readAllStandardOutput());
    }
    // 契约 3：destroyed/aboutToQuit 关 channel + 汇总断连，挂到 setOnClose
    a.setOnClose(detail::bind_close(proc, ch, {c1}));
    return a;                                    // 按值返回，move-only
}

} // namespace Coro
```

使用：`for (auto& chunk : generate(coroStdout(proc))) { ... }`。

### 6.2 范式二：多信号/多终止路径的来源——shared Awaitable + AutoDisconnect

适合：多条业务连接需要一起生死、终止路径多（正常关闭/错误/来源析构/应用退出）、或返回 `shared_ptr` 句柄的场景。参照 `corosocket.hpp` 等 socket 族：

```cpp
#include "awaitable.hpp"
#include "detail/autodisconnect.hpp"

namespace Coro {

/// 示例：QWebSocket 文本消息流
inline std::shared_ptr<Awaitable<QString>> coroTextMessages(QWebSocket* ws){
    auto awaitable = std::make_shared<Awaitable<QString>>();
    auto channel = awaitable->channel();          // 契约 1
    auto scope = detail::make_auto_disconnect();  // 连接组
    QPointer<QWebSocket> sock(ws);

    auto closeStop = [channel, scope]{
        channel->close();                         // 契约 2
        scope->disconnectAll();                   // 整组断开
    };
    if(sock){
        // 业务连接：只捕 channel
        scope->on(sock.data(), &QWebSocket::textMessageReceived,
                  [channel](const QString& msg){ channel->push(msg); });
        // 终止路径按业务需要接入
        scope->on(sock.data(), &QWebSocket::disconnected, closeStop);
        scope->on(sock.data(), &QObject::destroyed, closeStop);
        if(auto app = QCoreApplication::instance()){
            scope->on(app, &QCoreApplication::aboutToQuit, closeStop);
        }
    }else{
        channel->close();
    }
    // 契约 3 的关键：断连条件锚定返回句柄——
    // 消费者丢弃 shared_ptr（或显式 close）即整组取消订阅
    scope->untilExpired(awaitable);
    return awaitable;
}

} // namespace Coro
```

`AutoDisconnect` 提供的能力：
- `on(sender, signal, slot)`：建立并登记业务连接（可多条，一起生死）。
- `add(connection)`：登记已建立的连接（如跨 Qt 版本的错误信号封装）。
- `addCleanup(fn)`：登记随组清理执行一次的回调（如停止/删除定时器）。
- `untilExpired(awaitable)`：断连条件——返回句柄 `close`/析构即整组断开（经 `setOnClose`，只持弱引用、不延长句柄寿命）。
- `untilSignal(obj, sig)` / `untilSignal(obj, sig, pred)`：断连条件——某信号触发[且判断函数成立]即整组断开。
- `disconnectAll()`：显式整组断开（幂等）；`~AutoDisconnect` 析构兜底。

### 6.3 完成扩展后

- 一次性等待（等价 `waitForXxx`）：信号到达时 `channel->push` + `closeStop`，消费方 `await` 一次即得结果。
- 跨线程注意：来源对象的操作要在其所属线程执行；如需在建立时发起动作（如 `connectToHost`），用 `QMetaObject::invokeMethod(obj, fn, Qt::QueuedConnection)` 投递到对象线程。
- 自定义包装器与内置消费函数完全互通：`await` / `await_for` / `generate` 对按值 `Awaitable<T>` 与 `shared_ptr<Awaitable<T>>` 均可用。
- 建议为新来源补充 QtTest 用例（参照 `test/testfiberawait/`，其中 `test_case_autodisconnect_*` 演示了 AutoDisconnect 的行为约定）。

## 7. 常见问题排除

| 现象 | 原因与排除 |
|---|---|
| 主线程协程不执行 | 用了 `QCoreApplication::exec()`。改用 `Coro::exec()` |
| 程序结束不退出 / 退出崩溃 | 未调用 `Coro::quit()`；或 detached 协程在 `QCoreApplication` 析构后仍访问 Qt 对象 |
| 流式读取拿不到数据 | 检查是否对同一来源反复新建流式等待器却仍用旧句柄等待；应建一次、反复 `await`/`generate` |
| `deleteLater` 迟迟不生效 | 调度期不派发 `DeferredDelete`，到 `quit()` 排空才处理；需要即时释放用 `delete` |
| 改 `Affinity` 后协程未迁移线程 | 运行期迁移不受支持；创建时用 `Affinity` 指定 |
| 找不到 `coro(socket)` | 缺 `QT += network` 或未引入对应子头 / 伞头 `await/coro.hpp` |
| qmake 找不到 boost | 未按 §2.1 安装到 `/usr/local`，或未 `include(AsyncTask.pri)` |
