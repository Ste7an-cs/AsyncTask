# AsyncTask 软件需求规格说明

## 1. 范围

### 1.1 标识
- 软件名称：AsyncTask（用户态协程异步框架）
- 命名空间：`Coro`
- 版本：见代码仓库提交记录
- 适用对象：基于 Qt / C++17 的异步、IO 密集型应用开发

### 1.2 概述
AsyncTask 基于 `boost::fiber`（有栈协程）提供一套用户态协程异步框架。它将可暂停/恢复的逻辑封装为协程：协程被暂停时**让出所在线程而不阻塞该线程**，调用方可继续执行其它协程，待条件满足后协程被唤醒。

**解决的三个核心问题：**
1. **阻塞独占线程**——传统阻塞式 API（`waitForReadyRead`、`future::get`）会独占并阻塞整个 OS 线程，等待期间该线程无法处理其它工作。协程在等待时让出线程而非阻塞，使同线程可继续执行其它工作。
2. **回调地狱**——Qt 的异步来源（信号、socket 就绪）只能经信号槽回调获取，一段"连接→读→处理→再读"的逻辑被拆散到多个槽中，状态需在成员变量间传递、控制流难以跟踪。协程化等待将回调转为顺序书写。
3. **一任务一线程不可扩展**——在高并发下为每个任务创建系统线程带来的创建、切换与内存开销巨大。少线程上调度大量协程，切换在用户态完成、栈按需分配。

框架以头文件与静态库形式随宿主工程编译，依据宿主工程配置（是否含 Qt core / network）自动启用相应能力。

## 3. 需求

### 3.1 能力需求（RX_BASIC_ABILITY）

#### 3.1.1 协程创建与执行（R1_BASIC_ABILITY）

**3.1.1.1 功能需求**
应提供将可调用体作为用户态协程执行的能力：以任务形式创建协程并获取结果句柄；以低层接口创建带调度属性的协程；协程内让出/休眠。支持多协程间以捕获任务句柄并调用 get() 的方式汇合（让出式 join，不阻塞线程）。

**动因**：传统阻塞 API 独占线程；"一任务一线程"不可扩展。协程在等待时让出、同线程继续执行其它就绪协程，以顺序风格编写异步逻辑无需手动拆分回调。多协程并发时须有"等其它协程完成后再继续"的汇合手段（协作式 join）。

由此派生的动因型需求：
- **R1_MOT_1** 让出而非阻塞：协程在等待时应让出所在线程，使同线程可继续执行其它就绪协程。
- **R1_MOT_2** 顺序化书写异步：允许将异步等待以同步风格代码顺序书写，避免回调地狱。
- **R1_MOT_3** 少线程承载高并发：少量工作线程上并发调度大量协程，切换开销和内存远低于等量 OS 线程。

**3.1.1.2 输入输出**
- 输入：一个可调用体，以及可选的优先级、线程亲和、名称。
- 输出：一个任务对象句柄（可取回执行结果），或底层的 `boost::fibers::fiber` 对象。

**3.1.1.3 行为过程描述**
- 创建任务：使用方提交可调用体、即得任务对象；可调用体在协程中运行，创建方不被阻塞可继续其它工作。
- 获取结果：通过任务句柄取回返回值或错误；结果未就绪时的等待为**协程让出线程式**，不阻塞线程，同线程协程仍可推进。
- 多协程汇合：在协程中捕获其它协程的 FiberTask<T>，调用其 get() 等待完成——get() 以让出方式阻塞（不阻塞线程），多次 get() 即实现多协程 join。汇合点应在 shutdown 之前。
- 让出/休眠：协程可在等待或长耗时点主动让出线程，交还调度器以承载更多协程。

**3.1.1.4 行为参数**
- 优先级：低 / 普通 / 高（默认普通）。
- 线程亲和：共享（任意线程）/ 粘附（首次执行线程）/ 固定（指定线程），默认固定到创建时所在线程。
- 异常行为：可调用体抛出异常时在协程边界被捕获并转为错误结果（见 R4_BASIC_ABILITY），不跨协程传播。

#### 3.1.2 优先级与线程亲和调度（R2_BASIC_ABILITY）

**3.1.2.1 功能需求**
应提供在少量工作线程上调度大量协程的能力：三级优先级（高/普通/低）与三种线程亲和（共享/粘附/固定），支持跨线程工作分发，在线程无法运行协程的场景下（如主线程阻塞）也不丢失协程。

**动因**：需在不为一任务一线程的前提下承载高并发，同时兼顾任务轻重缓急与线程隔离要求（如 Qt 对象须在其所属线程访问）。解决方案是引入用户态协程调度：大量协程复用到少量工作线程，使用优先级表达轻重缓解，线程亲和表达固定/不固定在线程上的约束，无归属的共享协程在空闲线程间分发提升吞吐。

**3.1.2.2 输入输出**
- 输入：使用方创建协程时指定的优先级与线程亲和。
- 输出：协程在满足亲和约束的线程上按优先级被取用执行。

**3.1.2.3 行为过程描述**
- 就绪协程按线程亲和归组、组内按优先级排序，纳入跨线程共享的就绪集合。
- 各工作线程从中挑选满足自身亲和约束、优先级最高的协程执行；固定/粘附协程只被目标线程取走，共享协程可被任意空闲工作线程取走。
- 框架内置工作线程池（默认线程数按 CPU 核数确定）承接协程执行。
- 在无法运行协程的线程（如主线程阻塞于等待）上创建的共享协程，可由其它空闲工作线程取走执行，不被主线程阻塞拖住。

**3.1.2.4 行为参数**
- 亲和语义：共享=任意可用线程；粘附=绑定到首次执行它的线程；固定=绑定到指定的线程。
- 优先级：同一线程内高优先于普通、普通优先于低。
- 限制：**运行时反复更改线程亲和不受支持**（见 3.6 R1_OTHER），线程归属应在创建时确定。

#### 3.1.3 结构化并发（R3_BASIC_ABILITY）

**3.1.3.1 功能需求**
应提供任务链式编排能力：在前驱完成后自动以其结果为入参执行后继任务；在整条任务链全部结束时统一触发收尾回调；发起取消后，尚未开始的后续任务在启动前即短路并返回中断结果；取回任务结果时以协程让出方式等待而不阻塞线程。

**动因**：并发任务各自为战会出现"谁等谁、谁负责收尾、如何整体取消"无人管辖的问题。解决方案是将有依赖关系的协程组织为一条任务链：后继在前驱完成后自动以其结果启动（取代手写同步），结束回调在整链结束时统一触发（集中收尾），一处取消即让后继短路（整体可取消）。

**3.1.3.2 输入输出**
- 输入：一个已有任务、后继函数、结束回调（按操作而定）。
- 输出：后继任务对象；可取回最终结果。

**3.1.3.3 行为过程描述**
- 后继任务：前驱完成后自动以其结果为入参执行后继，后继默认沿用前驱优先级与线程模型；使用方以链式书写依赖关系。
- 结束回调：在整条任务链全部结束时统一触发，可登记多个，用于集中释放资源。
- 取消：对任务链发起取消后，尚未开始的后续任务在启动前短路、返回中断结果。
- 取结果：结果未就绪时以协程让出线程方式等待而不阻塞线程。

**3.1.3.4 行为参数**
- 前驱出错或任务链已被取消时，后继返回"中断"结果。
- 结束回调在任务链最后一个节点完成时触发，与 get() 的相对时序由实现保证。

#### 3.1.4 结果与错误传递（R4_BASIC_ABILITY）

**3.1.4.1 功能需求**
应提供承载"值或错误"的结果类型，支持无返回值场景（`void`）与携带错误码；禁止异常跨越协程边界传播。

**动因**：协程在不同线程上被调度、可被取消或超时。若让异常跨协程边界，将破坏结构化并发的确定性且难以在正确线程捕获。解决方案统一以结果对象承载成功值或错误码：协程内异常在边界被就地转为错误码结果，调用方以统一方式判断成败；取消、超时、通道关闭等也表达为错误码而非异常。

**3.1.4.2 输入输出**
- 输入：一个成功值，或一个错误码。
- 输出：结果对象，使用方判断成功/失败后取值/取错误/取默认值。

**3.1.4.3 行为过程描述**
结果对象承载成功值或错误二选一：失败时也可取默认值；支持 void 结果，可作为协程返回值与等待结果统一使用。

**3.1.4.4 行为参数**
- 结果为失败时取值操作返回不可用，应改取错误。
- 取消、超时、来源关闭、内部异常等均表达为相应错误码，而不抛出异常。

#### 3.1.5 统一协程等待（R5_BASIC_ABILITY）

**3.1.5.1 功能需求**
应提供统一的协程等待载体与工厂：单一重载入口 `coro(...)` 返回等待器或对象包装器；统一消费函数 `await`（取一次）与 `generate`（流式迭代）；等待器与具体来源（Qt / std）解耦，回调运行在 worker 协程而非调度器上下文，从而回调内可安全做协程阻塞。

**动因**：Qt 异步来源（信号、socket、IODevice、future）原生仅经信号槽回调获取，一段连续逻辑被拆散到多个槽中，状态散落成员变量；而 Qt 的 `waitForReadyRead` 同步等待会阻塞线程及事件循环。解决方案是将回调式来源统一封装为可 await 的等待器（回调转顺序等待），await 在无数据时让出协程而非阻塞线程（不阻塞事件循环），持续产生的事件可用 generate 像遍历容器一样顺序消费（流式消费，替代每次触发进一次回调的离散模型）。

由此派生的动因型需求：
- **R5_MOT_1** 回调转顺序等待：将信号/IO/future 等回调式来源封装为可 `await` 的等待器，使调用方以顺序写法取结果。
- **R5_MOT_2** 等待不阻塞事件循环：`await` 在无数据时让出协程而非阻塞线程，取代 `waitForXxx` 独占线程式的同步等待。
- **R5_MOT_3** 流式消费：持续产生的异步事件以 `generate` 像迭代容器一样顺序消费，替代离散回调模型。

**3.1.5.2 输入输出**
- 输入：Qt 信号（对象 + 成员函数指针）、Qt IO/socket/server 对象、`std::future` / `QFuture`。
- 输出：等待器或包装器（其方法返回等待器）；消费后得到一次结果或可迭代数据流。

**3.1.5.3 行为过程描述**
- 建立等待器：`coro(来源)` 把异步来源包装为可等待对象；对 socket/IO/服务器等，包装器方法名沿用原 Qt 命名，使用方无需学习新名字。
- 顺序取用：来源数据被送入等待器；使用方用 `await` 顺序取回一次结果，等待期间协程让出线程；也可带超时取用。
- 流式取用：对持续产生的事件用 `generate` 像迭代容器一样逐个取用。
- 自动收尾：来源对象销毁或应用退出时等待器自动关闭，正在等待/迭代的协程自然收敛；等待器 cross-thread safety、按值传递、RAII 析构取消订阅；等待器本体不含任何 Qt 类型，与来源解耦。

**3.1.5.4 行为参数**
- 信号参数⇒结果类型：无参→无返回值结果；单参→该值；多参→元组。
- 超时取值未在时限内到达数据 → 返回"超时"结果；来源已关闭 → 返回"无数据"结果，使循环自然结束。
- 接收数据类操作建立时若已有缓冲数据会立即投递，规避 check-then-wait 竞态。
- 使用方在协程执行期间等对象析构需注意其析构可能延后（见 3.6 R2_OTHER）。

#### 3.1.6 Qt 集成与安全退出（R6_BASIC_ABILITY）

**3.1.6.1 功能需求**
应提供与 Qt 事件循环共存的调度器、协程线程及应用集成与安全退出：调度器空闲时驱动 Qt 事件使二者共存且协程回调运行于 worker 上下文；`quit()` 流程广播退出→置全局退出标志→排空在途协程与事件→停线程池→退出，避免退出崩溃/卡死；主循环必须以 `Coro::exec()` 驱动且不得同时使用 `QCoreApplication::exec()`。

**动因**：Qt 应用原生由 `QCoreApplication::exec()` 的事件循环驱动，协程调度也需要一个循环来推动；二者在同线程若各跑各的会互相独占。解决方案是让协程调度器成为主循环并在其空闲时代驱动 Qt 事件，同时提供安全退出流程避免协程活过 Qt 应用对象而访问已销毁的事件系统。

**3.1.6.2 输入输出**
- 输入：`installFiberApplication()`、`Coro::exec()`、`Coro::quit()`。
- 输出：主线程/工作线程可同时调度协程与处理 Qt 事件；退出时干净收尾。

**3.1.6.3 行为过程描述**
- 事件共存：协程调度器在空闲（无就绪协程）时，由首次空闲时一次性创建、终身复用的常驻泵协程（每线程一个）在 worker 协程上下文里代为分发 Qt 事件；Qt 回调运行在 worker 协程（而非调度器 dispatcher 上下文），从而回调内可安全做协程阻塞（让出而非崩溃）。调度器自身以 cv 真正阻塞而非空转。
- 应用集成：`installFiberApplication()` 在主线程安装支持协程的调度器并启动工作线程池；`Coro::exec()` 让主线程留在协程调度器中（协程与 Qt 事件都能推进）；另提供支持协程的工作线程（QThread）以承载需固定线程的协程。
- 安全退出：`Coro::quit()` → ① 广播 `aboutToQuit` 唤醒挂起协程 → ② 置全局退出标志令各线程的常驻泵协程自行退出 → ③ 排空在途协程与事件（被唤醒的协程跑完、其投递的 `deleteLater` 处理完毕）→ ④ 停工作线程池 → ⑤ `QCoreApplication::exit()`。确保协程在 Qt 应用对象析构前收敛。

**3.1.6.4 行为参数**
- 主循环必须用 `Coro::exec()` 驱动，**不得用 `QCoreApplication::exec()`**（二者在同一线程互斥）。
- 协程调度期间 `deleteLater` 标记的对象一般到退出排空时真正析构（见 3.6 R2_OTHER）。

### 3.2 外部接口需求（RX_INTERFACE）

#### 3.2.1 接口标识和接口图
外部接口以 C++ 头文件形式提供，宿主工程通过 `include(AsyncTask.pri)` 引入。主要公开接口按功能分层：

```
任务层:  makeTask()  FiberTask<T>{then / on_finally / cancel / get}
应用层:  installFiberApplication()  Coro::exec()  Coro::quit()
等待层:  coro(...)  await(a [,timeout])  generate(a)
         Awaitable<T>  Generator<T>
基础层:  Result<T,E>  Coro::sleep  Coro::msleep  launch_properties()
```

#### 3.2.2 任务与应用接口（R1_INTERFACE）
- `makeTask(fn, pri=正常, affine=固定到当前线程) → FiberTask<T>`：以任务形式创建协程并返回结果句柄。
- `FiberTask<T>::then(fn [,pri,affine])`：创建以返回值类型为入参的后继协程。
- `FiberTask<T>::on_finally(cb)`：登记整条任务链结束回调。
- `FiberTask<T>::cancel()`：取消任务链，尚未开始的节点在启动时短路。
- `FiberTask<T>::get() → Result<T>`：以协程让出式等待取回结果。
- `installFiberApplication()`：主线程安装调度器并启动线程池。
- `int Coro::exec()`：进入主循环，等价于调度器阻塞基元的 `wait`。
- `Coro::quit()`：安全退出：广播 `aboutToQuit`→ 置全局退出标志 → 排空 → 停池 → 退出。

#### 3.2.3 等待接口（R2_INTERFACE）
- `coro(obj, &Obj::signal)` / `coro<Types...>(obj, &signal)` → `Awaitable<...>`：将 Qt 信号封装为等待器。信号参数打包规则：无参→无返回值；单参→该值；多参→元组。
- `coro(QAbstractSocket*)` ↓ `readAll()` / `waitForConnected()` / `connectToHost(...)` → `Awaitable<...>`：镜像原 Qt API 方法。
- `coro(QTcpServer*)` ↓ `nextConnection()` → `Awaitable<QTcpSocket*>`：镜像原 Qt API 方法。
- `coro(QIODevice*)` ↓ `readAll()` / `waitForReadyRead()` / `waitForBytesWritten()` → `Awaitable<...>`：镜像原 Qt API 方法。
- `coro(QLocalSocket*)` ↓ `connectToServer()` → `Awaitable<void>`：镜像原 Qt API 方法。
- `coro(std::future<T>&&)` / `coro(const QFuture<T>&)` → `Awaitable<T>`：future 转为等待器。
- `await(a) → Result<T>` / `await(a, timeout) → Result<T>`：取一次结果。
- `generate(a) → Generator<T>`：把等待器适配为可迭代数据流。
- 伞头 `await/coro.hpp` 一次性引入全部工厂；亦可按需单独引入各源码头（`corosignal.hpp` / `corosocket.hpp` / `corotcpserver.hpp` / `coroiodevice.hpp` / `corolocalsocket.hpp` / `corofuture.hpp`）。

#### 3.2.4 基础接口（R3_INTERFACE）
- `Result<T, E>`： `has_value()` / `value()` / `error()` / `value_or()`。
- `Awaitable<T>`： `channel()` / `setOnClose(fn)` / `await()` / `await_for(timeout)` / `resolve(v)` / `close()`。
- `Generator<T>`： `begin()` / `end()` / `next()` / `close()`，满足 C++ input iterator。
- `Coro::sleep(s)` / `Coro::msleep(ms)`：让出线程的协程休眠。
- `launch_properties(fn, pri, affine, name="") → boost::fibers::fiber`：以调度属性创建协程的底层入口。

### 3.3 内部接口需求（RX_IN_INTERFACE）

以下为框架内部模块间的职责契约，不对使用方开放（结构细节见设计文档）。

- **R1_IN_INTERFACE** 调度算法接口：框架须向 boost.fiber 提供一套调度算法，决定协程何时就绪、下一个运行哪个、无就绪协程时如何驱动 Qt 事件，并遵守 boost.fiber 对 `context` detach / attach 及 pinned 上下文约定的协定。
- **R2_IN_INTERFACE** 就绪协程集合存取：调度算法须能对内部就绪协程集合进行按线程亲和分桶入队、按亲和与优先级取出、按上下文移除等操作；跨线程访问须串行化以保证一致性。
- **R3_IN_INTERFACE** 线程挂起/唤醒：须提供"挂起线程但允许其继续调度协程"的基元，供工作线程池与协程线程在需要时挂起、退出时唤醒。

### 3.4 内部数据需求（RX_IN_DATA）

以下为框架内部维护的数据，不对使用方开放（结构细节见设计文档）。

- **R1_IN_DATA** 数据队列（FiberChannel）：跨线程、跨协程安全的数据队列，支持投递、取出（含超时）与关闭；作为等待器传递数据的底层载体。并发访问受 fiber mutex 保护。
- **R2_IN_DATA** 就绪协程集合（FiberGlobalQueue）：保存就绪协程，按线程亲和分组、组内按优先级排序，供调度按约束取用；并发访问由全局互斥量串行化。
- **R3_IN_DATA** 任务链状态（SharedState）：任务链各节点共享，含在途节点计数（原子）、取消标志（原子）、结束回调列表。
- **R4_IN_DATA** 协程调度属性（MetaContext）：每个协程携带的优先级、线程亲和与名称。线程亲和应在创建时确定、运行期不迁移。
- 数据一致性：上述并发数据须受相应原子/锁保护。

### 3.5 设计和实现约束（RX_DESIGN）

- **R1_DESIGN** 语言/标准：C++17（`gcc ≥ 9.0`）。
- **R2_DESIGN** 依赖：Boost ≥ 1.89.0（fiber / context / thread / chrono 组件，静态链接，安装于 `/usr/local`）；Qt ≥ 5.12（可选，依据宿主工程 `QT` 配置自动启用相关能力）。
- **R3_DESIGN** 构建：qmake；`include(AsyncTask.pri)`；依 `QT` 配置（core / network）自动启用 Qt 调度器与信号 / socket 等待能力。
- **R4_DESIGN** 体系结构：四层分层（detail → executor+scheduler → task → await），基于 boost.fiber 有栈协程，自定义调度算法实现优先级+线程亲和+跨线程分发。
- **R5_DESIGN** 等待载体解耦：等待器本体不含任何 Qt 类型，Qt 依赖集中在 `coro()` 工厂一侧并按来源类型拆分头文件，支持非 Qt 场合裁剪与非 Qt 来源扩展。
- **R6_DESIGN** 主循环模型：必须用 `Coro::exec()` 作为主循环（`QCoreApplication::exec()` 与协程调度同线程互斥）：调度器在空闲时以常驻泵协程（首次空闲时用 `std::call_once` 一次性创建、终身复用）在 worker 上下文驱动 Qt 事件，自身委托基类做真正的 cv 阻塞而不空转；退出时用全局 `static` 退出标志令泵协程自行终止避免 `~scheduler` 挂死。
- **R7_DESIGN** 平台：主要支持 Linux（x86_64）。

### 3.6 其他需求（RX_OTHER）

- **R1_OTHER** 已知限制—运行时改线程亲和：不允许在运行期反复更改线程亲和以迁移协程所在线程；高并发下会命中底层协程库跨线程迁移的时序缺陷，不保证迁移正确。线程归属应在创建时确定。
- **R2_OTHER** 已知限制—调度期 deleteLater：协程调度期间用 `deleteLater` 标记的对象一般到 `Coro::quit()` 排空时才真正析构；如需在协程执行期确定性地释放对象，应改用直接 `delete` 或另行处理。
- **R3_OTHER** 交付物：boost 1.89 源码包因体积未随仓库提供，需按 REF-1 自行下载编译安装到 `/usr/local`。
- **R4_OTHER** 测试：随仓库提供 5 套 QtTest 用例（testfibertask / testexecutor / test_scheduler / testfiberawait / testProfile）；testProfile 为长时间压力测试，超时属预期。

## 4. 注释

### 4.1 术语与缩写
| 缩写 / 术语 | 含义 |
|---|---|
| 协程 / fiber | 有栈用户态协程，暂停时让出线程、不阻塞线程 |
| Awaitable | 协程等待/数据载体，消费方使用 `await` 取值 |
| Generator | 把 Awaitable 当作数据流迭代适配器 |
| Affinity | 线程亲和模式：Shared（共享） / Sticky（粘附） / FixedId（固定） |
| Priority | 优先级：Low（低） / Normal（普通） / High（高） |
| SRS | 软件需求规格说明（Software Requirements Specification，本文档） |
| SDD | 软件设计说明（Software Design Description） |

### 4.2 需求标识说明
- `RX_BASIC_ABILITY`：能力需求，X 为能力序号（如 R1_BASIC_ABILITY = 协程创建与执行）。
- `RX_INTERFACE`：外部接口需求（如 R1_INTERFACE = 任务与应用接口）。
- `RX_IN_INTERFACE`：内部接口需求。
- `RX_IN_DATA`：内部数据需求。
- `RX_DESIGN`：设计和实现约束。
- `RX_OTHER`：其他需求。
- `Rx_MOT_y`：动因型需求，附属于对应能力需求（x=能力序号，y=动因序号），说明"为什么需要用协程解决"。
